# 中国网络下地图加载优化计划

更新时间：2026-10-01  
状态：代码实施与本地受控验证完成；真实提速、凭据可用性和中国多运营商验收仍待完成。2026-10-01 结果见 [验证记录](../artifacts/china-network/RESULTS.md)，完整范围见 [CHINA_NETWORK_SOL_TESTS.md](./CHINA_NETWORK_SOL_TESTS.md)。以下原始诊断与阶段建议保留供对照。

## 本轮实现与配置

- 新增自动、中国网络优先、全球网络三种配置，入口为图层设置中的“地图网络”。优先级：手动选择 > 部署设置 > 大陆时区与中文语言提示；提示不是 IP 或运营商定位。
- 读取可用的 `navigator.connection` 属性、在线状态，调整请求排队和超时；不降低 DPR、纹理或 LOD。未知网络保持 8 个并发，慢网/节省流量提示使用 4 个并发。
- 增加天地图 `vec_w`＋`cva_w` 街道与 `img_w` 卫星 WMTS 适配，当前配置 z1–18、Web Mercator；未接入非公开高德图片端点，不对天地图瓦片套用 GCJ-02 偏移。
- 默认同源模式在 `.env.local` 设置自己的 **`TIANDITU_TOKEN`**（适用于服务端调用），重启服务。密钥不返回客户端；`/__earth/network` 只告知是否配置及部署网络偏好。未配置时保留原来源并明确提示。
- 中国网络优先下，街道及 25 km 以下自动模式选择天地图街道，卫星/区域选择天地图影像；失败后在已配置的兼容来源间回退，卫星模式不切成街道。
- 改为必要的一层父图覆盖后直达目标 LOD，中心优先；路名渐进加载。增加有界超时、取消、错误分类、供应商冷却和来源切换期间的原图保留。
- 同源服务合并同瓦片进行中请求，继续遵守 HTTP 缓存及条件请求；处理 Retry-After、拒绝图、授权错误和冷却。不增加离线包或后台扫图。
- 暴露仅在浏览器会话内保存的聚合诊断，不记录精确坐标、IP、密钥或完整 URL。未采集 DNS/TLS 分项，不宣称已有运营商测速结论。

同源配置示例（密钥值需自行填写，不提交到仓库）：

```dotenv
TIANDITU_TOKEN=你的服务端授权密钥
EARTH_NETWORK_REGION=auto
```

若明确在国内线路部署，可将 `EARTH_NETWORK_REGION=china`；用户仍可手动覆盖。纯静态站点需设置 `VITE_DIRECT_TILES=true`、`VITE_NETWORK_REGION` 和单独授权的浏览器端 `VITE_TIANDITU_TOKEN` 后重新构建；此 Token 会公开在前端，不能填写服务端秘密。服务所在地仍会影响实际加载速度，本轮未迁移或发布远程服务。

## 目标与问题描述

用户反馈在中国大陆网络环境下，地球放大到街道级时地图可能加载很慢或无法加载。当前尚未在不同运营商、网络出口及目标部署位置完成对照测量，因此“无法加载”的直接原因仍待确认；可能涉及客户端网络、瓦片上游可达性、转发服务所在区域、供应商配额或地图源自身覆盖。

目标是在不违反地图数据许可的前提下，让中国大陆用户更稳定地看到城市与街道细节。优化结果需用可重复的网络指标验证，不能仅以更换域名或提高并发量作为成功标准。

## 实施前实现与已知风险（历史诊断）

- `src/layers/TileSources.ts` 中，`streets` 模式固定使用 OpenStreetMap 标准街道瓦片；在中国境内的 `auto` 模式放大到城市尺度时，当前选择逻辑也会切换到 OSM。
- 默认请求先到同源 `/__tiles/{source}/{z}/{x}/{y}`，再由 `server/tile-relay.mjs` 请求上游。用户所处网络与转发服务器所在网络都可能影响体验；当前没有按中国区域选择瓦片服务的配置。
- 页面能显示来源、LOD、加载进度和失败状态，也会保留父级瓦片或全球底图；没有按供应商细分的连接耗时、首字节时间、失败类型及 p50/p95 报告，也没有跨来源自动切换。
- 当前默认 OSM 公共瓦片服务明确为尽力而为、无 SLA，并要求可识别应用、遵守缓存和避免批量下载；它不能作为面向中国用户的稳定性承诺。[OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)

## 实施阶段

### 1. 建立中国网络基线

使用固定、少量的验收视图测试当前加载链路，建议覆盖北京、上海、广州、成都的城市与街道高度。对中国电信、联通、移动的家庭 Wi-Fi 与移动网络分别记录；同时标明测试设备、日期、当前来源、LOD 和服务部署位置。

每个视图记录以下数据：

- 首批可见瓦片成功率、最终可见范围覆盖率、失败数与超时数。
- DNS、连接、TLS、首字节及下载耗时；汇总中位数与 p95。
- HTTP 状态与错误类别、瓦片大小、当前并发数、队列等待时间。
- 客户端直连与当前 Node 转发路径的对照结果，用于定位问题发生在终端网络、转发链路还是上游。

调试日志只保存来源、请求时间、层级和错误类别，不收集用户精确位置或其他不必要的个人信息。测试只访问预先选定的屏幕视野，不执行区域扫图或离屏预取。

### 2. 评估适用于中国网络的地图源

建立经授权的候选源清单，优先核实可在中国大陆使用、提供正式 Web/移动 SDK 或栅格/矢量瓦片接口、服务配额明确且许可适合本项目发布方式的来源。首轮可评估天地图的 Web API / 瓦片资源，以及高德开放平台面向 WebGL 和移动端的 JS API / SDK；这些官方能力是否能以合规方式接入当前 Three.js 球体和瓦片网格，仍需做小规模概念验证。[天地图平台建设说明](https://www.gov.cn/zhengce/zhengceku/202403/P020240312438108110230.pdf)说明其 Web API 支持栅格及矢量瓦片；[高德 JS API 2.0 文档](https://lbs.amap.com/api/javascript-api-v2/summary/)说明其 WebGL 地图引擎适配 PC 与移动端。

对每个候选逐项确认：

- 接口是否为官方公开并授权给本项目使用；不得逆向或依赖未公开的地图图片地址。
- 能否为 Three.js 球体提供可用的瓦片/图层，投影、瓦片矩阵、最大级别、覆盖范围及纹理格式是什么。
- Key、域名白名单、应用类型、调用配额、速率限制、署名、缓存和商用条款。
- 对第三方地图、其他数据源叠加或同屏展示是否有限制。高德 Web 服务 API 使用条款包含关于同时使用第三方地图服务的限制；须按具体产品条款审查，不能默认该 API 可与现有来源混用。[高德 Web 服务 API 使用条款](https://developer.amap.com/pages/law-web-service)
- 坐标系如何与项目的 WGS84 地球模型衔接。国内地图服务可能使用不同坐标基准；高德文档提供 GPS 等坐标转高德坐标的接口，项目应在每个 `TileSource` 适配层显式处理转换，避免道路与地球地理位置错位或重复转换。[高德坐标转换文档](https://lbs.amap.com/api/webservice/guide/api/convert)

### 3. 设计分区来源与失败回退

- 为中国大陆增加经过实测和授权的来源适配器；保留海外现有来源，来源选择由地域、地图模式、授权配置和数据覆盖共同决定。
- 瓦片无法连接或出现持续超时时，先保留已显示的父级图像和 NASA 全球底图；达到明确失败阈值后再切换到有授权的备用源，并在状态条显示实际来源。
- 切换来源时保留原图覆盖，避免因失败闪白或空洞；避免多个供应商同时重复请求同一视野。
- 按当前可见区域优先级调度瓦片。现有并发队列为 8；需先依据基线测量判断是否调整，不盲目提高并发导致运营商限流或服务端拒绝。
- 按供应商缓存规则复用已加载瓦片，并使用其公开的 HTTP 缓存头及条件请求；不把服务端内存缓存误称为离线地图，也不增加后台扫图。

### 4. 部署与中国大陆发布检查

若测试显示转发服务器到地图源的线路是瓶颈，评估在目标用户附近部署正式地图服务或使用供应商提供的国内服务节点。部署前确认服务资格、数据存储位置、地图审核、备案、数据安全及供应商授权要求；具体适用义务交由项目发布审查确认，本计划不构成法律结论。

手机 App 在中国大陆登载地图时，应把地图来源、审核要求及 App 备案纳入发布评估。主管部门通知提及地图审核、ICP备案、地图来源与审图号等要求；实施前按届时有效规定确认本项目的具体适用范围。[自然资源部、工信部关于 App 登载使用地图的通知](https://hnca.miit.gov.cn/zwgk/tzgg/tz/art/2024/art_270c90866b994bb69a020ce812de6278.html)；[《地图管理条例》](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)。

中国大陆 App 发布的整体要求另见 [APP_RELEASE_PLAN.md](./APP_RELEASE_PLAN.md)。

## 验收目标（初始建议）

用第一阶段基线确认目标后，可将下列数字作为试运行门槛，再按选定供应商 SLA 和真实设备修订：

- 指定运营商与测试城市中，街道视图首屏可见瓦片成功率不低于 98%。
- 从进入街道预设到目标视野至少 95% 瓦片显示，p95 不超过 5 秒；每项报告必须附网络类型、测试地点、来源和日期。
- 网络超时后，全球底图和已有父级覆盖始终可见；来源切换与手动重试可恢复加载。
- 测试截图、瓦片成功率、p50/p95、失败来源、API 配额与许可审查结果归档在 `artifacts/` 和项目文档中。
- 在预先选定的固定视图和运营商网络上完成验收；结果不外推为中国所有地区、时段和网络均有同样性能。
